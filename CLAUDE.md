# Notes for agents

Things in this project that have surprised agents before. Read the README for how it works; this file is about what isn't obvious from it.

## Deployment

- Production is the `spread-book` container on the Docker host `nuc1`, reached as `core@nuc1`. Deploy from this checkout with `docker -H ssh://core@nuc1 compose -f docker/compose.yaml up -d --build`. The image is built on nuc1, but `docker/.env` is read from this machine, so it has to exist locally (it's gitignored; copy `docker/.env.example` and fill it in).
- Check what's actually running on nuc1 before assuming it matches the repo. Until 2026-09-30 nuc1 still ran the old `optionspread-heatmaps` container with named volumes, several commits behind. Starting `spread-book` next to it would have published twice per run.
- Data and reports are bind-mounted from `/var/home/core/spread-book/{data,reports}` on nuc1. The old named volumes `optionspread-heatmaps_data` and `optionspread-heatmaps_reports` are a leftover backup from the migration, not in use.
- `SHARED_DIR` (set in the gitignored `docker/.env`, required by `compose.yaml`) is a host directory shared with the equity-watch container, mounted at `/app/shared`. Keep it separate from `reports/`, which `publish.sh` syncs to S3, and from `data/`. It must be mounted as a directory with `:z`, and be owned by uid 1000, because equity-watch (uid 1000) writes `betas.json` into it by renaming a temp file; this container runs as root and can write anywhere. equity-watch runs a beta job there on weekdays at 08:05 and 14:05 Denver. Compose's `env_file` also passes `SHARED_DIR` into the container as that host path, so scripts must use the fixed `./shared` and never read `$SHARED_DIR`.
- Publishing is two cron jobs, not one: `fetch.sh` (7:45, 13:25) downloads and writes `shared/underlyings.txt`; `publish.sh` (8:10, 14:10) builds from that CSV. The 8:10 and 14:10 times sit after equity-watch's beta job, so change them together with its schedule, and keep the gap under `report.sh`'s 90-minute limit. Don't reunite them: the beta job needs the ticker list before the report can use its betas.
- The S3 bucket, IAM user and CloudFront distribution still carry the old `optionspread-heatmaps` name. That's deliberate: renaming them would recreate the resources. Don't "fix" it.
- The site's hostname was taken out of the repo on purpose (commit 8d8c5ab). Don't add it back to tracked files. Ask the developer, or read the `SiteUrl` output of the `spread-book` CloudFormation stack.

## Verifying a publish

- The container's IAM user (`optionspread-heatmaps-billbaran-docker-publish`) can only list the bucket, write and delete objects, and create invalidations. It can't read objects or describe CloudFront, so `aws s3api head-object` or `aws cloudfront get-invalidation` fail with 403/AccessDenied inside the container. That's least privilege, not a broken deploy. Verify from outside: fetch the public URL (e.g. `/latest.json`), or use the developer's local AWS credentials.

## Republishing an old snapshot

- To redo a report without a new download, run `/app/publish.sh data/<csv>` in the container. `publish.sh` never downloads (that is `fetch.sh`); with no argument it takes the newest CSV and refuses one more than 90 minutes old, and a named CSV skips that check.
- `portfolio.js` refetches underlying prices every time it runs and overwrites `<base>-prices.json`. Regenerating an old snapshot therefore uses current prices, which skews the delta and gamma split in that run's P&L attribution (the total is unaffected). The same prices are saved in the snapshot as `spots`, so the report's "To short strike" column and `latest.json`'s `sigmaToShortStrike` are wrong for a regenerated old snapshot too: today's price against that day's strikes, IV and days left.

## Code

- Calculations belong in `book.js`, not `report.js`: anything that decides a number or an order on the page (grouping, sorting, medians, totals, parsing a pasted trade) is a function there with a test in `test/calc.test.js`. `report.js` should only turn those results into HTML. It has no unit tests of its own, so logic left in it is untested; `test/page.test.js` loads the whole page in jsdom against `test/fixture.js` as a safety net.
- `page.js` builds the HTML for both `portfolio.js` and the page tests, so what the tests load is what gets published. The Dockerfile's `COPY *.js` picks it up. jsdom is a devDependency: don't move it to `dependencies`, which would put it in the image.
- `book.js` runs in two places: `require`d by `brief.js` in Node, and inlined into every report ahead of `report.js`, where it sets `globalThis.SpreadBook`. Keep it free of Node APIs and `require`. Exit rules belong there, not in `report.js`, so the page and `latest.json` agree.
- `RULES.strikeSigma` (0.5) is deliberately not 1.5. OptionStrat's PoP implied these spreads start about 0.5 to 1.4 expected moves from the strike (median about 0.9, from the March sample), so a 1.5 threshold would flag the whole book. The first live book (2026-10-12, 13 spreads) agreed: 0.50 to 1.12, median about 0.9, and 0.5 flagged one spread, the one with the lowest PoP. Reasonable, but one day's data: look again after a few weeks and across volatile weeks before treating it as tuned.
- Beta-weighted delta (`betaWeight` in `book.js`) relies on the export's Delta being in share-equivalents for the position as held: per-share delta × 100 × contracts. Both parts are verified. The ×100 shows in the March sample (an AAPL put spread at 5.99, and single-contract long calls, not in the book, at 93.5, 80.6 and 77.8). The developer checked in OptionStrat on 2026-10-12 that doubling the contract count doubles Delta and every other greek, so a multi-contract spread needs no adjustment. The samples can't show that themselves, since every leg in them has quantity ±1. Betas older than `RULES.betaMaxAgeDays` (10) at the snapshot are ignored, but a beta file written after the snapshot is fine, because equity-watch's job runs after the download.
- The heatmap sections titled "... by underlying and expiration" have one row per underlying *and spread kind* (`put`, `call`, `other`; see `renderHeat` in `report.js`), not per underlying. So two spreads on the same symbol share a row only if they are the same kind: two Bull Puts do, a Bull Put and a Bear Call (an iron condor's legs) don't. That is by design, not a duplicate-row bug.
- `entry` and `closed` in `latest.json` are built by `brief.js` from every `*-portfolio.json` in `reports/`, not just the newest. Deleting old snapshots there changes them: a spread that was open in the (new) oldest snapshot becomes `entry: { known: false }`, and one that appeared right after the deleted ones looks as if it were opened then. Don't prune `reports/`. Re-running `brief.js` on an old snapshot only looks at snapshots up to that one.
- A spread is identified across snapshots by name, expiration and strikes (`spreadKey`). Rolling to new strikes or a new expiration is a close plus a new spread. The same key starts a new episode (`reopened`) after a gap of one or more loaded snapshots, or when its credit or max loss changes by a cent. A snapshot that fails to parse is not loaded, so it is neither presence nor absence. Don't "fix" a bad export by writing an empty snapshot in its place: that reads as everything closing. A close and reopen at the same credit between consecutive snapshots can't be seen.
- `creditToWidthPct` divides by `maxProfit + maxLoss`, not by `width × 100`, because the export has no contract count and its credit and risk cover all contracts held. The two are equal for one contract.
- `sim.js` (the exit plan and the "from here" simulation) is Node only and must never be inlined into the page: `portfolio.js` runs it once and stores `plan`, `fromHere` and `recovery` on each position, and the page and `brief.js` only read them. Its pricing and path code is a port of spread-scanner's `src/outcome.ts`, deliberately duplicated rather than shared (no build step here, TypeScript there). Change one, change the other. `test/sim.test.js` compares the two when spread-scanner is checked out next to this repo, and skips that test otherwise.
- `SIM.ivDecay` in `sim.js` (0.35) is calibrated, not derived: spread-scanner fitted it so its simulation reproduced the owner's record of closed spreads. It tilts every "from here" result a little toward holding, so a spread held from the stop can come out a few points better than closing now. That is the assumption, not an edge. Don't present `fromHere` as a forecast, and don't write copy saying a spread "will" recover.
- The stop in the simulation is judged at each simulated close, as in the scanner's calibration. The exit plan's stock prices are for checking the stop during the day. They are approximate (one IV for both legs) and change as days pass. equity-watch watches them every 15 minutes (the next point). It judges the stock price, not the spread's mark; a mark-based alert from Schwab option quotes is a later phase.
- `shared/spread-alerts.json` (written by `brief.js` through `spread-alerts.js`) is the complete set of stop alerts equity-watch should hold, and equity-watch cancels any stop that is missing from it. So never write it from a partial or old view of the book: `brief.js` writes it only for the newest snapshot, `complete` is false when the snapshot has no exit plans, and an open spread with no stock level today goes in `unpriced` (kept) rather than being left out (cancelled). An export with no spreads at all makes `portfolio.js` exit before anything is written, so closing every spread leaves the old stops until the next export that has spreads; equity-watch's page flags levels older than 30 hours. The equity-watch side is `src/spreads/` there, documented in its `docs/SPREADS.md`.
- Each spread's OptionStrat link (the saved trade, quantity included) exists only as a hyperlink in the downloaded `.xlsx`; the CSV keeps the cell's text, "Open". `spread-alerts.js` reads the links from the `.xlsx` beside the snapshot's CSV and passes them to equity-watch in the shared file only. Keep them out of the snapshot JSON, the report and `latest.json`, which are public.
- Regenerating an old snapshot recomputes `plan` and `fromHere` with today's Yahoo prices (see "Republishing an old snapshot"), so those are wrong for it in the same way as `sigmaToShortStrike`.
- `publish.sh` uploads `reports/` only, never `data/` (since 2026-10-24). The raw exports in `data/` carry each spread's OptionStrat saved-trade link, quantities and entry prices, and the site is public. They live only on nuc1's `data` bind mount, which since 2026-10-24 is the only copy: the older exports that were only on S3 were moved there and deleted from the bucket. Don't clear that directory, and don't add the upload back as a backup.
- `#try=` in the report's URL is spread-scanner's "Try in spread-book" button (`spreadBookUrl` in its `web/model.js`). `readTry` and `tryTrade` in `book.js` turn it into a trial trade, converting the scanner's per-share greeks and fractional IV into the export's units ((bought − sold) × 100 × contracts, IV in percent) and naming it the way OptionStrat does, so its `spreadKey` matches the export's. The payload is a contract between the two repos: change one, change the other (the scanner's `test/web.test.ts` runs this reader against its encoder). The page reads it on load and on `hashchange`, then clears the fragment, so a reload doesn't add it again. Trial trades are never saved.
- Paper trades (`paper.js`) must stay out of the real book. Their snapshots go to `reports/paper/` (`portfolio.js --paper`), because `brief.js`, `daily-pnl.js` and the real index read `reports/` itself, not its subdirectories: a paper snapshot there would join the real history, `latest.json` and the stop alerts equity-watch acts on. Don't run `brief.js` or `daily-pnl.js` on them. A paper snapshot is the OptionStrat export's CSV built from the ledger, which is the seam AUTOMATION-PLAN.md section 4 describes for a ledger replacing the export.
- `data/paper/ledger.json` has one writer, `paper.js`, under `data/paper/.lock`. A ledger that fails to parse is an error, never an empty ledger, and a snapshot with any open trade unquoted isn't written (a missing spread reads as closed). `tastytrade.js` is a port of spread-scanner's quote calls (CommonJS, like `sim.js`). Its credentials are spread-book's own read-only OAuth client, `TASTYTRADE_*`, not the scanner's `TT_*`.
- `data/` is gitignored, but the three March 2026 CSVs in it are tracked as sample data for testing the pipeline locally.
